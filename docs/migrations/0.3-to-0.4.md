# Migrating from Rheo 0.3 to 0.4

v0.4.0 is **additive**. Existing 0.3 supervision trees, consumers, and
`Rheo.query/2` callers keep working.

## What you gain

| Area | API |
|---|---|
| Richer search | `:after_sequence`, `:until_sequence`, lineage metadata filters |
| Pagination | `Rheo.query_page/2` → `%Rheo.Page{}`; `Rheo.stream_query/2` |
| Safe replay | `create_group(..., start_after: n)` / `start_at: datetime` |
| Re-consume | `Rheo.replay/3` (`from_sequence:`, `from:`, `query:`) |
| Hard reset | `Rheo.reset_group/3` with **`confirm: true`** |
| Lineage | `Rheo.Event.Lineage.put/2` / `get/2` |

## What you should not change casually

- Do **not** treat `Rheo.query/2` as a way to rewind a production group.
- Prefer a **new replay group** with a start cursor over resetting a live group.
- `reset_group` clears that group’s deliveries only; events stay immutable.
  Without `confirm: true` you get `{:error, :confirm_required}`.

## Optional adoption

```elixir
# Paginate
{:ok, page} = Rheo.query_page("market-events", type: "curve_update", limit: 100)

# Replay isolation
Rheo.create_group("market-events", "risk-replay", start_after: 1_000)

# Lineage on append
meta = Rheo.Event.Lineage.put(%{}, correlation_id: "trade-42", producer: "pricing")
Rheo.append("market-events", %{type: "curve_update", metadata: meta})
```
