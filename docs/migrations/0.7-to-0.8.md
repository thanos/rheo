# Migrating from 0.7 to 0.8

v0.8.0 is an architectural reset. Delivery guarantees (at-least-once, lease
fencing, partitions, contiguous frontier, replay) are unchanged. The consumer
callback, the local group lifecycle, the capability declaration, and the
settlement error vocabulary change so that a native-stream backend such as
Redis Streams can be added in v0.9 without another core rewrite.

See [ADR 019](019-v0-8-architectural-reset.html).

## Summary

| Area | Change |
|---|---|
| `Rheo.Consumer` | Handlers return `:ack`, `{:retry, reason}`, or `{:reject, reason}`; the second argument is a read-only context |
| Local groups | `use Rheo.Consumer` is a child spec for `Rheo.Group`; no bridge; one Group per `{rheo, stream, group}` per node |
| `Rheo` instance | `:backend` is required; the `url:` shorthand raises unless `Rheo.Backend.Mongo` is available |
| `%Rheo.Lease{}` | New `:receipt` field for backend-native settle identity |
| `Rheo.Backend` | `capabilities/0` returns a `Rheo.Backend.Capabilities` struct; settle errors use the `Rheo.Settle` vocabulary |
| `Rheo.Producer` | `ack/3`, `nack/4`, `reject/4` settle and confirm in one call; `confirm/2` remains |
| Dependencies | Integrations are optional: add only the drivers you use |

## Dependency changes

`mongodb_driver`, `ecto`, `ecto_sql`, `gen_stage`, and `broadway` are now
optional. Add the ones you use next to `:rheo`:

```elixir
{:rheo, "~> 0.8.0"},
{:mongodb_driver, "~> 1.5"},   # Rheo.Backend.Mongo
{:ecto_sql, "~> 3.11"},        # Rheo.Backend.Ecto (+ postgrex or ecto_sqlite3)
{:gen_stage, "~> 1.2"},        # Rheo.Producer
{:broadway, "~> 1.2"}          # Rheo.Broadway
```

A host that upgrades without adding them loses the corresponding modules at
compile time (`UndefinedFunctionError` on first use). ETS needs nothing
([ADR 020](020-package-and-dependency-boundaries.html)).

## Consumer callback changes

Before (0.7):

```elixir
def setup(_opts), do: {:ok, %{processed: 0}}

def handle_event(event, state) do
  :ok = work(event)
  {:ack, %{state | processed: state.processed + 1}}
end
```

After (0.8):

```elixir
def setup(opts), do: {:ok, %{counter: Keyword.fetch!(opts, :counter)}}

def handle_event(event, %{counter: counter}) do
  :ok = work(event)
  :ok = MyApp.Counter.increment(counter)
  :ack
end
```

`setup/1` receives every option given to the child spec, so pass application
processes through it. Returning a non-map from `setup/1` stops the Group with
`{:invalid_context, value}`.

## Group lifecycle changes

`{MyApp.RiskConsumer, opts}` now starts the `Rheo.Group` directly under your
supervisor. Remove any `:name` option you gave the consumer; the Group is
registered under a local name derived from `{rheo, stream, group}`. A second child for the same
`{rheo, stream, group}` on one node fails with
`{:error, {:already_started, pid}}` instead of sharing the group. Scale local
work with `:concurrency`; scale across nodes with one consumer per node.

`Rheo.Group.drain/2` no longer blocks the group while waiting; it replies
when inflight work settles or the timeout fires.

## Instance changes

```elixir
# before
{Rheo, url: "mongodb://localhost:27017/rheo"}

# after
{Rheo, backend: {Rheo.Backend.Mongo, url: "mongodb://localhost:27017/rheo"}}
```

The `url:` shorthand still works while `Rheo.Backend.Mongo` ships in the same
package; without an explicit `:backend` and without that module, `Rheo`
raises `ArgumentError` at start. `config :rheo, start_on_application: true`
now needs `config :rheo, backend: ...` (or the legacy `:mongo_url`).

## Lease changes

`lease_id` remains the fencing token. `lease.receipt` carries an opaque
backend-native identity (database backends set it to `lease_id`; a Redis
backend will store the stream entry id). Do not pattern-match on its contents.

## Backend author changes

The callback list is unchanged. What changed:

| Callback | 0.7 | 0.8 |
|---|---|---|
| `capabilities/0` | flat boolean map | `Rheo.Backend.Capabilities.new/1` struct; unknown keys and non-boolean values raise; `at_least_once` and `lease_fencing` cannot be `false` |
| `fetch/4` | leases without `receipt` | set `receipt` when the store has a native claim identity (or to `lease_id`) |
| `renew/3`, `ack/2`, `retry/3`, `reject/3` | `{:error, :stale_lease}` on a token mismatch | additionally `{:error, :receipt_mismatch}` when a set receipt differs |
| any callback | driver exception structs in `{:error, _}` | `:backend_unavailable`, `{:failed, cause}`, `{:ambiguous, cause}` (`Rheo.Settle`) |

The conformance suite (`test/support/backend_contract.ex`) is grouped by
guarantee and also runs against a native-stream test double.

## Producer, Broadway, and Flow

Broadway pipelines are unchanged: `Rheo.Producer` plus
`Rheo.Broadway.transform/2` (with `gen_stage` and `broadway` in your deps).
The acknowledger now settles through
`Rheo.Producer.ack/3`, `nack/4`, and `reject/4`.

Plain GenStage consumers should replace the two-step settle:

```elixir
# before
:ok = Rheo.ack(lease, rheo: MyRheo)
Rheo.Producer.confirm(producer, lease.lease_id)

# after
:ok = Rheo.Producer.ack(producer, lease, rheo: MyRheo)
```

The settlement boundary for GenStage, Broadway, and a future Flow integration
is the same: a lease is settled when the durable result it contributed to
exists, and the producer helper releases the inflight entry in the same call.
For `Flow.reduce` or windows, call the helper from `on_trigger` after the
aggregate is stored, never inside the reducer. Flow is not shipped in v0.8.

## Query and sequence

`event.sequence` remains the portable per-partition order. `Rheo.Query.new/2`
normalizes `order_by` directions `1` / `-1` to `:asc` / `:desc`; backends only
accept the atoms.

## Telemetry

Event names are unchanged. Error metadata now carries a `Rheo.Settle` reason
instead of a raw driver term: `[:rheo, :fetch, :error]`,
`[:rheo, :ack | :retry | :reject, :error]`, and the `:result` of
`[:rheo, :lease, :renew]`. `[:rheo, :handler, :error]` is new and fires when a
handler raises or throws.

## Minimal upgrade example

```elixir
# mix.exs
{:rheo, "~> 0.8.0"},
{:ecto_sql, "~> 3.11"},
{:postgrex, "~> 0.19"}

# supervision
children = [
  {Rheo, name: MyRheo, backend: {Rheo.Backend.Ecto, repo: MyApp.Repo}},
  {MyApp.RiskConsumer, rheo: MyRheo, concurrency: 8}
]

# consumer
@impl true
def handle_event(event, _context) do
  :ok = MyApp.handle(event)
  :ack
end
```
