# Migrating from 0.7 to 0.8

v0.8.0 is an **architectural reset**. Runtime delivery guarantees
(at-least-once, fencing, partitions, frontier, replay) are preserved, but
several public APIs and dependency shapes change so Rheo can host a future
Redis Streams backend without another core rewrite.

See [ADR 019](https://hexdocs.pm/rheo/019-v0-8-architectural-reset.html).

## Summary

| Area | Change |
|---|---|
| Dependencies | Optional / split packages — see below |
| `Rheo.Consumer` | Handler returns `:ack` / `{:retry, reason}` / `{:reject, reason}`; context is read-only |
| Local groups | One runtime per `{rheo, stream, group}` per node; duplicate child specs error |
| `%Rheo.Lease{}` | Optional `:receipt` for backend-native settle identity |
| Backend authors | Capabilities v2 + thinner semantic contract |
| Producer | Prefer settle helpers that also confirm; `confirm/2` remains for GenStage |

## Dependency changes

Prefer:

```elixir
{:rheo, "~> 0.8.0"}
# plus only what you use:
{:rheo_mongo, "~> 0.8.0"}       # MongoDB
{:rheo_ecto, "~> 0.8.0"}        # PostgreSQL / SQLite via host Repo
{:rheo_broadway, "~> 0.8.0"}    # Rheo.Producer + Broadway
```

ETS remains in core `:rheo` (no extra package).

If you stay on the transitional single-package build, Mongo/Ecto/Broadway deps
are **optional** — add them explicitly in your app.

## Consumer callback changes

Before (0.7):

```elixir
def handle_event(event, state) do
  :ok = work(event)
  {:ack, %{state | n: state.n + 1}}
end
```

After (0.8):

```elixir
def handle_event(event, context) do
  :ok = work(event)
  Agent.update(context.agent, &(&1 + 1))   # app-owned state
  :ack
end
```

Outcomes: `:ack` | `{:retry, reason}` | `{:reject, reason}`.

## Group lifecycle changes

Do not start two `Rheo.Consumer` bridges for the same `{rheo, stream, group}`
on one node. Scale with `:concurrency`. Across nodes, one local runtime each.

## Lease changes

`lease_id` remains the fencing token. Backends may set `lease.receipt` with an
opaque native identity (e.g. future Redis PEL entry). Domain code should not
pattern-match on receipt contents.

## Backend author changes

- Implement `Rheo.Backend.Capabilities` guarantees/mechanisms (ADR 023).
- Prefer semantic settle APIs; keep row/document algorithms private.
- Native-stream backends must settle using receipt + fencing, not only Rheo
  delivery rows.

## Producer / Broadway / Flow

Broadway usage is unchanged in spirit (`Rheo.Producer` + `Rheo.Broadway.transform/2`).
Install via `:rheo_broadway` when packages are split.

Flow is **not** shipped. Settlement for reduce/window must retain leases until
aggregates are durable — see the Flow readiness spike under Design docs.

## Query / sequence

`event.sequence` remains Rheo's portable per-partition order. No change to
`Rheo.query/2` filters for ordinary apps.

## Telemetry

Existing `[:rheo, …]` events remain. Settlement may emit explicit
`[:rheo, :settle, …]` results (`:ok`, `:stale_lease`, `:error`).

## Minimal upgrade example

```elixir
# mix.exs
{:rheo, "~> 0.8.0"},
{:rheo_broadway, "~> 0.8.0"}

# consumer
def handle_event(event, _ctx), do: (MyApp.handle(event); :ack)
```
