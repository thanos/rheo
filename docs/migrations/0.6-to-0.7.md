# Migrating from Rheo 0.6 to 0.7

v0.7.0 is **additive**. `Rheo.Consumer`, `Rheo.Group`, the backends, and every
public function behave exactly as in 0.6. What is new is a second way to consume
a durable group: a GenStage producer, plus the glue to run it under Broadway.

The one change you will notice is that Rheo now depends on `gen_stage` and
`broadway`.

## What you gain

| Area | API |
|---|---|
| GenStage producer | `Rheo.Producer` — emits `%Rheo.Lease{}` |
| Broadway transformer | `{Rheo.Broadway, :transform, []}` |
| Broadway acknowledger | `Rheo.Broadway.Acknowledger` (attached automatically) |
| Settle notification | `Rheo.Producer.confirm/2` |
| Drain | `Rheo.Producer.drain/2` plus Broadway's `prepare_for_draining/1` |

## Using Broadway

```elixir
defmodule MyApp.RiskBroadway do
  use Broadway

  def start_link(_opts) do
    Broadway.start_link(__MODULE__,
      name: __MODULE__,
      producer: [
        module:
          {Rheo.Producer,
           rheo: MyRheo, stream: "market-events", group: "risk", max_demand: 50},
        transformer: {Rheo.Broadway, :transform, []},
        concurrency: 1
      ],
      processors: [default: [concurrency: 8]]
    )
  end

  @impl true
  def handle_message(_processor, message, _context) do
    case Risk.process(message.data) do
      :ok -> message
      {:error, reason} -> Broadway.Message.failed(message, reason)
    end
  end
end
```

`message.data` is the `%Rheo.Event{}`. `message.metadata` carries `:lease`,
`:stream`, `:group`, `:partition`, and `:attempt`.

## Using plain GenStage

The producer emits leases, so Broadway is optional:

```elixir
{:ok, producer} =
  Rheo.Producer.start_link(rheo: MyRheo, stream: "market-events", group: "risk")
```

Your consumer settles each lease **and** tells the producer, so renewal stops and
a demand slot is released:

```elixir
def handle_events(leases, _from, state) do
  Enum.each(leases, fn lease ->
    :ok = Risk.process(lease.event)
    :ok = Rheo.ack(lease, rheo: MyRheo)
    Rheo.Producer.confirm(state.producer, lease.lease_id)
  end)

  {:noreply, [], state}
end
```

`Rheo.Broadway.Acknowledger` does both steps for you under Broadway.

## Choosing between Consumer and Producer

`Rheo.Consumer` remains the default. It needs no extra topology: a
`handle_event/2` callback and a supervised `Rheo.Group` that owns fetch,
concurrency, lease renewal, and settle.

Use `Rheo.Producer` when you want Broadway's topology — batching, rate limiting,
fan-out into several batchers, or joining an existing pipeline.

Pick **one per `{rheo, stream, group}`**. Running both is competing consumers, and
the backend arbitrates leases as usual, but it is rarely intentional.

## Compatibility notes

- `gen_stage` and `broadway` are hard dependencies, for the same reason `ecto_sql`
  is: `Rheo.Producer` and `Rheo.Broadway.Acknowledger` compile against those
  behaviours rather than `Code.ensure_loaded?/1` guards. A package split is
  deferred — see ADR 018 "Alternatives".
- `:max_demand` on the producer bounds **unsettled leases**, not pipeline
  concurrency. Broadway's `processors: [default: [concurrency: n]]` is a separate
  knob; setting it far above `:max_demand` starves processors.
- Failures map to `Rheo.nack/3` by default and to `Rheo.reject/3` with
  `on_failure: :reject` on the producer, or per message via
  `Broadway.Message.configure_ack(message, on_failure: :reject)`.
- Delivery is still at-least-once. Use `message.metadata.attempt` to detect a
  redelivery and keep handlers idempotent on `Rheo.Event.id`.
- Partitions still require a static `:partitions` assignment; automatic
  rebalancing is not implemented.
- New telemetry: `[:rheo, :producer, :start | :stop]` and
  `[:rheo, :broadway, :ack | :retry | :reject]`. The producer reuses
  `[:rheo, :lease, :renew]` and `[:rheo, :fetch, :error]`.
