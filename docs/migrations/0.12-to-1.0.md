# Migrating from 0.12.0 to 1.0.0

v1.0.0 is the **SemVer baseline** for the surface frozen in v0.12.0
(ADR 029 / ADR 030). Consumer / Event / Query / Backend callback meanings are
unchanged. There are **no intended breaks** for hosts already on 0.12.0.

See the [changelog](https://hexdocs.pm/rheo/changelog.html#100---2026-09-20)
and [ADR 030](https://hexdocs.pm/rheo/030-semver-1-0.html).

## Summary

| Area | Change |
|---|---|
| Version policy | SemVer applies to Facade / Consume / Values / Backend / Runtime |
| Public surface | Same HexDocs inventory as 0.12.0 |
| Optional ops | Still non-SemVer-core (may evolve in 1.x minors) |
| Features | None — promotion of the freeze, not a feature release |

## What stays the same

Everything from the [0.11.1 → 0.12](0-11-1-to-0-12.html) migration, including:

- Composite `query_page` cursors; legacy `%{after_sequence: n}` still accepted
- `fetch(missing_stream, group)` → `:stream_not_found`
- ETS / Mnesia `atomic_compare_and_set: false`
- `{Rheo, url: …}` Mongo shorthand when `mongodb_driver` is present
- Portable error atoms (`:stale_lease`, `:backend_unavailable`, …)

## What hosts should do

1. Bump the dependency:

       {:rheo, "~> 1.0"}

2. Prefer modules under HexDocs **Facade / Consume / Values / Backend /
   Runtime**. Treat Mix tasks and LiveDashboard as convenience ops.

No code changes are required if you only used the 0.12 public APIs.

## What backend authors should do

Nothing beyond staying on the published `Rheo.Backend` contract and
conformance suite. Ops callbacks remain optional (`{:error, :unsupported}`).

## After 1.0

- **Patch (1.0.x):** correctness and docs on the frozen surface
- **Minor (1.x):** additive APIs; optional ops may move
- **Major (2.x):** breaking changes to frozen contracts

Multi-node Mnesia and a first-class Flow package remain deferred.
