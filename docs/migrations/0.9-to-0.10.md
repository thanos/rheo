# Migrating from 0.9 to 0.10

v0.10.0 is **additive**. Consumer / Event / Query semantics and all settle paths
are unchanged. The release adds a library-first **ops surface**: inventory, DLQ
listing, group health, optional metrics/LiveDashboard, and Mix inspect tasks.

See [ADR 027](https://hexdocs.pm/rheo/027-ops-surface.html).

## Summary

| Area | Change |
|---|---|
| Inspect APIs | `Rheo.list_streams/1`, `Rheo.list_groups/2`, `Rheo.dead_letters/3`, `Rheo.group_info/3` |
| Backends | Shipping backends implement matching optional callbacks |
| Telemetry | Documented events; optional `Rheo.Telemetry.Metrics` |
| LiveDashboard | Optional `{:phoenix_live_dashboard, …}` enables thin Rheo page |
| Mix | `mix rheo.streams`, `mix rheo.lag`, `mix rheo.dead_letters`, `mix rheo.group_info` |
| Breaking | None intended for v0.9 hosts |

## New inspect APIs

```elixir
{:ok, streams} = Rheo.list_streams(rheo: MyRheo)
{:ok, groups} = Rheo.list_groups("orders", rheo: MyRheo)
{:ok, dead} = Rheo.dead_letters("orders", "risk", limit: 50, rheo: MyRheo)
{:ok, info} = Rheo.group_info("orders", "risk", rheo: MyRheo)
```

Custom backends that do not export the new callbacks receive
`{:error, :unsupported}`.

## Optional LiveDashboard

```elixir
{:rheo, "~> 0.10.0"},
{:phoenix_live_dashboard, "~> 0.8"}
```

Register the Rheo page in your Phoenix router’s LiveDashboard (see the
[ops guide](ops.html)). ETS/Redis/Mongo-only hosts never pull Phoenix.

## If you stay on 0.9 APIs only

No code changes. New Mix tasks and inspect APIs are opt-in.
