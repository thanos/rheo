# Migrating from 0.11.1 to 0.12.0

v0.12.0 is an **API freeze candidate**. Consumer / Event / Query / Backend
callback meanings are unchanged from 0.11.1. There are **no intended breaks**
for hosts already on 0.11.1.

See the [changelog](https://hexdocs.pm/rheo/changelog.html#0120---2026-09-20)
and [ADR 029](https://hexdocs.pm/rheo/029-api-freeze-candidate.html).

## Summary

| Area | Change |
|---|---|
| Public surface | HexDocs publishes the freeze (Facade / Consume / Values / Backend / Runtime / Ops) |
| Internal modules | `Rheo.Instance`, `Rheo.Names`, table engine stay out of the published module list |
| Contract | Unavailable-handle mapping is part of the conformance suite |
| Optional ops | LiveDashboard / Mix inspect / Metrics remain non-SemVer-core |

## What stays the same

- Composite `query_page` cursors (`%{partition => after_sequence}`); legacy
  `%{after_sequence: n}` still accepted
- `fetch(missing_stream, group)` → `:stream_not_found`
- ETS / Mnesia `atomic_compare_and_set: false`
- `{Rheo, url: …}` Mongo shorthand when `mongodb_driver` is present
- `ack/2` / `nack/3` / `reject/3` honour only `:rheo` in opts

## What hosts should do

Nothing required to upgrade if you only use the 0.11.1 public APIs. Prefer
depending on modules listed under HexDocs **Facade / Consume / Values /
Backend / Runtime**. Treat Mix tasks and LiveDashboard as convenience ops.

## What backend authors should do

Keep implementing `Rheo.Backend` as documented. Ops callbacks remain optional
(`{:error, :unsupported}`). Map dead handles and driver disconnects to
`:backend_unavailable` (or `{:ambiguous, :timeout}` for in-flight write
timeouts). The conformance suite includes an unavailable-handle case.

## After 0.12

0.12.x patches are correctness-only on the frozen surface. **1.0.0** starts
SemVer for `Rheo` / `Rheo.Consumer` / `Rheo.Backend`. Multi-node Mnesia and a
first-class Flow package remain deferred.
