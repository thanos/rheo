# Migrating from Rheo 0.5 to 0.6

v0.6.0 is **additive**. Nothing changes for existing Mongo or ETS instances —
0.6 only adds a third backend. The one thing you will notice is that Rheo now
depends on `ecto` and `ecto_sql`.

## What you gain

| Area | API |
|---|---|
| SQL backend | `{Rheo.Backend.Ecto, repo: MyApp.Repo}` |
| PostgreSQL | `Ecto.Adapters.Postgres`, claims via `FOR UPDATE SKIP LOCKED` |
| SQLite | `Ecto.Adapters.SQLite3`, zero-service durable local runs |
| Schema | `Rheo.ensure_indexes/1` or `mix rheo.ecto.gen_migration` |
| Dialect-aware flags | `Rheo.Backend.Ecto.capabilities/1` |
| Wakeup hint | `notify: true` → `NOTIFY rheo_events` (PostgreSQL only) |
| Schema prefix | `prefix: "rheo"` (PostgreSQL) |

## Using the Ecto backend

Your application owns the repo. Rheo borrows it and never starts the pool:

```elixir
children = [
  MyApp.Repo,
  {Rheo, name: MyRheo, backend: {Rheo.Backend.Ecto, repo: MyApp.Repo}}
]
```

Create the schema either on boot:

```elixir
:ok = Rheo.ensure_indexes(rheo: MyRheo)
```

…or as a normal migration, which is preferable in production because it runs
once under your release's migration step:

```console
mix rheo.ecto.gen_migration --repo MyApp.Repo
mix ecto.migrate
```

Rheo creates five tables: `rheo_streams`, `rheo_stream_sequences`,
`rheo_events`, `rheo_groups`, and `rheo_deliveries`. On PostgreSQL, `metadata`
and `payload` are `jsonb`, so you can query the event log directly:

```sql
SELECT id, sequence, payload->>'currency'
FROM rheo_events
WHERE stream = 'market-events' AND payload->>'currency' = 'EUR'
ORDER BY partition, sequence;
```

## Compatibility notes

- `ecto` and `ecto_sql` are now hard dependencies. `postgrex` and `ecto_sqlite3`
  stay optional — add the one your repo uses. If you only use Mongo or ETS you
  gain two transitive deps and nothing else.
- SQL only. `mongodb_ecto` and other non-SQL Ecto adapters raise at start;
  use `Rheo.Backend.Mongo` for MongoDB.
- SQLite declares `distributed: false`. Concurrent claims are safe on one node,
  not across a shared filesystem. Use PostgreSQL for multi-node deployments.
- `capabilities/0` reports the PostgreSQL defaults. Call
  `Rheo.Backend.Ecto.capabilities(:sqlite)` or pass a live handle for the flags
  that actually apply to an instance.
- Timestamps are stored as `timestamptz` on PostgreSQL and fixed-width ISO 8601
  text on SQLite. `DateTime` values inside a payload are serialized to ISO 8601
  strings, because both dialects store payloads as JSON. Mongo, which has a
  native date type, still round-trips them as `DateTime`.
- `NOTIFY` is a wakeup hint, not a delivery guarantee. Consumers still poll; the
  contiguous frontier and lease fencing are unchanged.
