# Migrating from Rheo 0.4 to 0.5

v0.5.0 is **mostly additive**. Streams with `partition_count: 1` (the default)
keep working. Multi-partition streams change sequence semantics.

## What you gain

| Area | API |
|---|---|
| Partitions | `create_stream(..., partition_count: N)` |
| Key routing | append `:key` → `:erlang.phash2(key, N)` |
| Explicit partition | append `:partition` |
| Contiguous frontier | advanced on ACK/reject; holes block progress |
| Lag | `Rheo.lag/3` → `%Rheo.Lag{}` |
| Ownership groundwork | Consumer/Group `:partitions` (`:all` or list) |
| Scoped replay | `replay` / `reset_group` `:partition` / `:partitions` |

## Compatibility notes

- Sequences are monotonic **within a partition**, not across the stream.
- Do not assume global order when `partition_count > 1`.
- Legacy stream docs with a single `next_sequence` are treated as partition `0`.
- Dead-letter (`reject`) **unblocks** the frontier for that sequence (documented
  in ADR 016).
- `create_group(..., start_after: n)` applies `n` to **all** partitions unless
  you pass `:partition` / `:partitions`. Prefer a map when needed:
  `start_after: %{0 => 10, 1 => 0}` (integer or string keys).
- New streams with `partition_count > 1` use per-partition counters only. There
  is no automatic rewrite of rare 0.4 multi-partition layouts that still used a
  stream-global sequence.

## Example

```elixir
Rheo.create_stream("market-events", partition_count: 4)
Rheo.create_group("market-events", "risk")

Rheo.append("market-events", %{type: "curve_update", key: "EUR-EURIBOR-6M", price: 2.9})

{:ok, lag} = Rheo.lag("market-events", "risk")
# lag.partitions[p].lag == high_watermark - frontier

{MyApp.RiskConsumer, partitions: [0, 1], concurrency: 4}

Rheo.replay("market-events", "risk", from_sequence: 0, partition: 1)
```
