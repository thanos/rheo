# Migrating from 0.8 to 0.9

v0.9.0 is **additive**. Delivery semantics and the v0.8 Consumer API are
unchanged. The release adds an optional **Redis Streams** backend and implements
the wakeup hint path (ADR 025).

See [ADR 026](https://hexdocs.pm/rheo/026-redis-streams-backend.html).

## Summary

| Area | Change |
|---|---|
| Dependencies | Optional `{:redix, "~> 1.5"}` enables `Rheo.Backend.Redis` |
| Backends | New Redis Streams adapter (Model C receipts) |
| Runtime | Optional wakeup reader Task when the backend supports `wait/2` |
| Breaking | None intended for v0.8 hosts that do not use Redis |

## Enabling Redis

```elixir
{:rheo, "~> 0.9.0"},
{:redix, "~> 1.5"}
```

```elixir
children = [
  {Rheo,
   name: MyRheo,
   backend: {Rheo.Backend.Redis, name: MyRheo.Redis, host: "127.0.0.1", port: 6379}}
]
```

Requires Redis **6.2+**. Default docker-compose service: `redis` on `6379`.
Override with `RHEO_REDIS_URL=redis://localhost:6379`.

## Wakeup

Groups and Producers still poll. When the backend exports `wait/2`, Rheo starts
a short-lived reader Task that may send an early `:fetch` hint. Lost or
spurious wakeups only affect latency.

## If you stay on ETS / Mongo / Ecto

No code changes. Do not add `redix` unless you use Redis.
